# 制作者向け接続ガイド

[English（主文書）](CREATOR_GUIDE.en.md) · [简体中文](CREATOR_GUIDE.zh-CN.md)

対象：1.2.0 / アセンブリ 1.2.0.0。これは実装仕様の説明であり、今回のゲーム内動作確認済みという意味ではありません。

## 1. 動作と前提

ゲームの BoardingLeft / BoardingRight 信号を読み、左右の開度を独立して計算します。毎フレーム、閉扉バインド姿勢に移動量を加えてボーンを動かします。シミュレーション時刻を使うため、一時停止中は開度を保持します。

実行時の車両に Train、PrefabRef、InterpolatedTransform、Bone、Skeleton が必要です。RenderPrefab 側には正しい ProceduralAnimationProperties、ProceduralBone、バインドインデックスとスキニングが必要です。車種名を付けるだけでは条件を満たしません。別の交通種別も実行時データを確認してください。

## 2. Blender とインポート

1. 既存プロジェクトを別バージョンとして保存し、実寸・単位・軌間設計を維持します。本 Mod は形状や軌間を変更しません。
2. 閉扉状態をバインド姿勢とし、ドア板・一緒に動くガラス・ゴム・縁を対応ボーンに割り当てます。固定枠は車体に残します。
3. 剛体のドアは通常、そのボーンへ完全にウェイトを割り当てます。車体ウェイトの混入やバインド後の無計画な変換適用は変形の原因になります。
4. 車体とガラスを別メッシュで出力する場合、双方に一致する門ボーンとバインド位置が必要です。ガラスだけ静的メッシュにすると追従しません。
5. 骨格・スキン付き FBX を車両アセットとしてインポートします。ゲームのドアボーン用途を None=0 とし、台車やパンタグラフの用途は維持します。
6. 保存・再読み込み後も骨情報を確認し、寸法・材質・ガラスを点検します。静的エディタープレビューには乗降信号がないため、実路線で検証します。

アニメーションクリップは不要です。親ボーンが回転している場合、標準の +Z/-Z は車体の前後方向にならないことがあります。骨格を調整するか、親座標を考慮した JSON を使います。

## 3. 公共のボーン命名規則

`ReDoor_<L/R>_<正の門組番号>_<0/1>_<行程mm>`。`TrainReDoor_` も使えます。大文字・小文字を区別します。

```text
ReDoor_L_01_0_850
ReDoor_L_01_1_850
ReDoor_R_01_0_850
ReDoor_R_01_1_850
```

- L/R は作者側のラベルです。実際のホーム側はゲーム座標の object X で判定します。
- 門組番号は正の Int32 で、01 のような先頭ゼロを使えます。4 組という制限はありません。
- 0 は親座標 +Z、1 は -Z へ移動します。方向番号はホームの左右とは独立です。
- 行程は 1～10000 mm。`640.5` のように小数点を使えます。

原生 X<0 が Left、X>0 が Right です。abs(X)<0.0001 m は自動判定しません。エクスポート時の軸変換で L/R の文字と実際の側が逆になる場合があります。文字だけで修正せず、ゲーム上の位置を確認してください。中心線ボーンには JSON の Left/Right を明示します。

## 4. 任意のボーン名を JSON で指定

[完全な例](../examples/CustomTrain.example.json)の bindings に、実際の RenderPrefab 名とボーン名を正確に指定します。プラットフォームの表示名や Blender オブジェクト名とは限りません。車体と別ガラスにはそれぞれのメッシュ名で指定します。

```json
{
  "mesh": "MyTrain",
  "bone": "PassengerDoor_A",
  "side": "Auto",
  "deltaMeters": [0, 0, 0.85]
}
```

side は Left、Right、Auto のみ。Auto は原生 X を使用します。deltaMeters は親座標のメートル単位で、ベクトル長は 0.001～10 m です。0.85 m は 850 mm です。斜めの直線移動は可能ですが、外へ押し出してから横へ動く多段階プラグドアではありません。

openSeconds / closeSeconds は全体共通の 0.05～60 シミュレーション秒です。優先順位は excludedMeshes、JSON、公共命名規則の順です。重複や不正な値があるとカスタム設定全体が既定値へ戻り、エラーを記録します。

読み込むのはコントローラーの隣の TrainReDoor.json 一つだけです。車両フォルダーの JSON の自動検出・結合や登録 API はありません。Loaded ログに実際のパスが出ます。変更後はゲームを再起動してください。更新時に手編集の設定が置換される場合があるため、公開車両には公共命名規則を推奨します。

## 5. 検証とトラブル対応

一つのコントローラーと対応車両を有効にし、Loaded と該当メッシュの Bound ログを確認します。Bound は骨の一致を意味するだけで、正しいウェイトや方向を証明しません。

| 現象 | 確認する箇所 |
| --- | --- |
| Loaded がない | 再生セット、DLL の配置、重複や他の制御 Mod |
| Bound がない | Train 条件、RenderPrefab、骨名、None 用途、バインドインデックス |
| ガラスだけ動かない | 独立ガラスのボーンとスキニング |
| 反対側が開く | 原生 X、軸変換、JSON の明示的 side |
| 方向が違う | 0/1、親座標の回転、JSON ベクトル |
| 形が崩れる | 頂点ウェイト、バインド姿勢、車体の誤った割当 |
| 設定が反映されない | ログの設定パス、再起動、解析エラー、正確な名前 |

左右ホーム、逆向き編成、各車両、ガラス同期、一時停止・再開、乗降終了時の閉扉、保存・再読み込みを確認します。台車など他のボーンも確認し、実施したゲーム・アセット・Mod の版と結果だけを記録します。

## 6. 車両の公開

既存の Train ReDoor 条目（Mod ID 164831）を依存先に指定してください。サンプル ID は使わず、車両に別のコントローラー DLL を同梱しません。規則に従う制作者は C# の変更やコンパイルを行う必要はありません。

対象は平行移動式の引き戸です。回転式ドア、多段階プラグドア、音、衝突、発車インターロック、乗客経路制御は含みません。扉が完全に閉まるまで出発を待つ機能はありません。[検証範囲](VALIDATION.md)。
